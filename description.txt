# Introduction

In this project we build an Event Recommender app for Linz.
In this application, the users are asked to write their personal interests and pick other optional parameters (like tags, curated-only events and so forth) and the application will pick for them 10 best-matching events.

# How the search works
This application combines both metadata filtering and chain-based semantic search. First the application filters the data using the metadata specified by the user.

As the next step, an agent is given with the user's typed preferences and is tasked to write a query which is simple enough for embedding-based search of documents. Then the generated query is transformed into embeddings and the application uses cosine similarity to sort and choose the top 10 events based on the query. These top 10 generated queries are displayed on the screen

## Additional details displayed on the event card
You can see that apart from the self-explanatory data, like event title, description, location and so forth, there are other AI-generated details, like **matching score** or **💡**:

- **Matching score** is determined by the cosine similarity of the query's and the event's embedding vector. It should tell how much the current event is relevant to the user.

- **💡** is essentially a short description of why the event should be interesting to the user generated by the agent. The prompt is engineered in such a way that it tries to address the user directly for better performance.

# What's in the repo
- data/       Raw and derived datasets: City of Linz open data, the Ars
              Electronica Festival Notion export, and a precomputed OpenAI
              embedding vector database used for retrieval.
- notebooks/  Exploratory data analysis over both data sources.
- backend/    FastAPI service: semantic search over the event catalog,
              interest-text validation and query rewriting via a LangChain
              agent, and per-event match explanations.
- frontend_1/ An experimental fork of frontend/ (mobile-style swipe deck
              with real drag gestures, no sidebar) kept isolated so it's
              trivially reversible.
- docs/       Reference material the frontend's screen flow was built from.
